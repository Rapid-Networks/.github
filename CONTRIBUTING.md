# Contributing

Thanks for your interest in contributing! Please read our
[Code of Conduct](CODE_OF_CONDUCT.md) before taking part.

## Workflow

1. Fork the repo (or, if you're on the team, create a branch) from `main`,
   named `feature/short-description` or `fix/short-description`.
2. Keep changes focused. One concern per PR.
3. Run the project's checks before pushing (`make check` where available).
4. Open a PR using the template and link the related issue.
5. At least one review is required before merging.

For larger changes, please open an issue first so we can agree on the
approach before you put time into it.

## Commits

Write short, imperative commit messages ("Add retry to Splynx client").

## Code standards

- Follow the conventions in the repo's README and the existing code.
- New behaviour needs tests.
- Never commit secrets. Use environment variables and provide a `.env.example`.

## Licensing

By contributing, you agree that your contributions are licensed under the
licence of the repo you're contributing to.

## Questions

See [SUPPORT.md](SUPPORT.md), or reach out to dev@rapidnetworks.co.za.
